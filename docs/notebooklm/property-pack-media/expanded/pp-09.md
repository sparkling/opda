# How evidence becomes a reviewable model

For working-group participants and modelling facilitators.

A useful model begins with questions that people need to answer. Which property does this record describe? Who supplied this information? Is a missing value genuinely absent, not applicable, unknown, or simply not yet collected? A file format can arrange answers without settling these questions. The evidence-to-model approach makes the intended meaning explicit and gives practitioners something concrete to challenge.

Accepted ADR-0063 establishes domain-led modelling and human ownership of meaning. Proposed ADR-0065 describes a fuller AI-assisted operating cycle. That proposal is a documented direction, not an already ratified standards lifecycle. The working method visible in the member guide is simpler: collect authorised evidence, expose questions, produce a versioned candidate, review its meaning and revise it visibly. The status of each actual candidate must still be established from its own record.

## Start with evidence that can answer a question

Relevant material includes forms, dictionaries, schemas, policies, examples, diagrams and transcripts. Different sources do different jobs. A regulator's publication may establish an obligation within its stated scope. A company's schema shows an implementation convention. A practitioner example can demonstrate an exception. A meeting discussion can reveal a disagreement. None should be flattened into a generic collection of equally authoritative statements.

The source record needs origin, version, date, permitted use, applicable context and a stable reference. For a large document, the modelling claim should identify the relevant passage while retaining the complete source's context. A contributor's explanation helps distinguish a normative rule from an organisation's preferred practice. Missing access or uncertain rights are part of the evidence state, not reasons to invent what the source probably says.

For the Property Pack, the accepted business-data boundary is unusually concrete: 451 workbook items. The evidence catalogue records source facts and structural corroboration separately from proposed semantic decisions. This separation lets a reviewer correct a candidate definition without rewriting the historical source, or challenge a source constraint without pretending it never existed.

## Move from a source question to a semantic proposition

Consider an illustrative repeated question about whether a utility service is connected. The source may place several yes/no leaves beneath different utility headings. A direct field-to-predicate conversion would preserve the layout but could miss the recurring idea of a service record connected to a property. The modeller investigates whether the repeated questions concern the same kind of thing, what distinguishes each instance and which attributes belong on it. Consolidation is justified by meaning and evidence, not merely by similar spelling.

The same investigation asks what the answer means. A permitted value of Unknown is different from a missing response. Conditional requiredness describes when an answer is required; it is not an additional answer value. A branch may require an answer only after another condition is established. Treating that requirement as unconditional would create false validation errors, while dropping the condition entirely would lose a source obligation.

These propositions become a connected package. The glossary gives a plain-language definition. The dictionary explains a data element and its value expectations. A controlled vocabulary supplies governed choices. Resources identify the things being described, relationships connect them, and taxonomies organise concepts where broader and narrower meaning is useful. SHACL shapes then express the checks chosen for a specific graph or profile. The outputs should explain the same decision from different viewpoints.

## Use tools to expose uncertainty

AI can extract candidate terms, compare sources, draft definitions and suggest alternative structures. It can also repeat a source error, invent a connection or make two genuinely different meanings look identical. Multiple agents provide useful challenge, but their agreement is not independent industry consensus. Domain specialists remain responsible for deciding whether the proposal reflects their work.

A good draft therefore preserves alternatives and unresolved questions. For example, a proposed identifier might refer to a physical property, a legal title or an address record. The modeller should make that ambiguity visible and ask for cases where those identities diverge. A polished diagram that quietly chooses one interpretation is less useful than an explicit question linked to evidence.

The July working-method research describes a broad completeness checklist. The later September amendment to accepted ADR-0063 governs the current required method: eight retained categories covering domain structure; vocabulary and taxonomy; classification metadata; provenance and quality; access and sensitivity; validation; time and history; and cross-domain mappings. Earlier descriptions of eleven lenses must not be presented as the current category count. Each category can be modelled locally, reused, contributed at a boundary, or marked not applicable with a reason.

## Check different kinds of correctness separately

RDF parsing checks whether a file can be read as RDF. SHACL evaluates the encoded graph constraints. Coverage checks whether source items have traceable dispositions. A competency query tests whether the representation can answer a stated question. Reproducible generation checks whether the same maintained input produces the same artefacts. Each check contributes evidence, but none establishes that the underlying account is factually true.

An address can satisfy a minimal presence rule while containing a real-world error. A property relationship can parse correctly while pointing in the wrong direction. A source catalogue can cover every selected row while its definitions remain disputed. Review works best when reports say which question was tested, against which input and with which expected result.

## Turn feedback into a visible next candidate

Participants review definitions, examples, diagrams and consequences rather than being required to write ontology syntax. Useful feedback identifies the affected item or version, describes the practical problem and supplies evidence or a counterexample. The response should explain whether the issue was accepted, needs evidence, was deferred or falls outside the agreed scope. A disagreement can remain open without disappearing from the record.

The next candidate incorporates adjudicated changes and preserves an inspectable difference from the previous one. This prevents a reviewer from discovering that the object they commented on has silently changed. The cycle is successful when people can trace a source through a proposal, a challenge and a reasoned disposition. Faster drafting helps that cycle; authority still comes from the appropriate human decisions.
