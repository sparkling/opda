# Reading linked data and understanding what an implementation proves

For implementers, technical reviewers and practitioners who want to inspect the model.

Linked data gives resources explicit identities and expresses relationships as statements. In the Property Pack candidate, a property, an address, a controlled value and a validation shape are different resources with different jobs. An ontology browser helps a person inspect those resources. Turtle files preserve the RDF statements; SPARQL queries inspect graphs; SHACL checks selected constraints. These mechanisms support review, but none independently confers standards approval or verifies a property's real-world condition.

The repository contains several distinct bodies of work. The preserved schema-derived ontology is OPDA's derivation from the PDTF schema. The Property Pack 0.1 candidate is a separate first-principles proposal seeded by the selected workbook scope. Accepted ODR-0065 defines namespace policy for a new governed model, with implementation in ontology artefacts explicitly pending. An implementer must identify the corpus and version before comparing names or reusing a query.

## Read identifiers before abbreviations

The preserved schema-derived family uses `https://opda.org.uk/pdtf/`. The immutable candidate uses `https://w3id.org/opda/candidate/property-pack/0.1/` and context-specific namespaces below it. The accepted new-model policy uses `https://opda.org.uk/ns/` with peer context spaces, a reviewed common boundary and separate instance identities under `/id/`. ODR-0065 does not migrate the candidate or rewrite the preserved corpus.

Prefixes are convenient local abbreviations. In one file `opda:` can expand to the historical `/pdtf/` namespace; in another it can expand to the new `/ns/` policy. The expanded identifier determines what the statement names. A matching prefix or local word does not establish identity between corpora, and a changed prefix alone need not change the identifier.

The new namespace policy separates vocabulary identity from document location and release information. A page can move without renaming a governed term. Equally, an HTTP-shaped identifier does not prove that a representation resolves today or that content negotiation is implemented. The policy explicitly leaves publication behaviour to separate delivery evidence. Its illustrative names are naming examples, not approved terms.

## Inspect the resource's job and its connections

A class describes a kind of thing. A property expresses a relationship or attribute. A vocabulary member supplies a governed value within its scheme. A shape states selected requirements for a validation target. A context gives semantic ownership; a work package organises work. These distinctions prevent a browser's convenient grouping from becoming an unintended assertion about the model.

The candidate's address-separation competency query supplies a concrete example. Its ASK pattern checks that `pds:Address` is an OWL class and that `pds:hasAddress` has declared domain `common:Property` and range `pds:Address`, using the candidate namespace bindings. The relationship runs from the property to the address. The query does not ask whether a particular dwelling's address is correct or whether every instance supplies one.

RDFS domain and range statements describe semantic entailments. They are not, by themselves, document-validation instructions that reject an unexpected subject or object. The repository's execution profiles also matter: a query over asserted triples and a query over an entailment-expanded graph can observe different statements. An implementer should state which graph and inference behaviour a check uses, rather than infer them from a diagram.

## Ask what a check actually establishes

The candidate's property-identity query checks for the declared Property class and the `uprn` property's domain and string range. It tests a structural modelling proposition. It does not establish that an input identifier is assigned, unique for every intended entity or suitable for resolving every transaction question. Those require appropriate evidence and rules.

Another candidate query asks whether any `owl:sameAs` statement occurs; its expected result is false. That is a guard against unsupported identity assertions in the inspected candidate. It is not a philosophical claim that two records can never describe the same entity. The precise query and expected result matter more than a label such as “identity test.”

SHACL validation is similarly bounded. A conforming result means the supplied graph passes the selected shapes under the chosen execution configuration. Missing constraints cannot fail, and a well-formed false statement can satisfy structural rules. Positive examples show intended acceptance; negative examples show that a relevant defect is actually rejected. Accepted ADR-0037 selects Apache Jena for the repository's RDF, SHACL and SPARQL work; older examples using a different RDF validation stack should not be treated as the current OPDA instruction.

## Mapping requires semantic decisions as well as syntax

The historical PDTF-to-RDF work uses RML to read source JSON and emit statements in the schema-derived ontology. Accepted ADR-0057 records its implementation and later amendments, including replacement of the initially selected morph-kgc engine by RMLMapper. Its chronology is valuable evidence of problems discovered and corrected; the initial engine choice and early coverage totals are not the final state.

One concrete problem was controlled-value identity. A source string such as “Legal Owner” does not automatically become the correct scheme member by inserting it into a URL template. The recorded implementation used exact controlled-value mappings where generic encoding would produce a different identifier. A syntactically valid IRI can still name the wrong or a nonexistent vocabulary resource.

Another problem concerned correlated array data. The ADR records a case where projecting multiple array-valued fields independently created combinations that did not belong together. Two reports with different results could become four subject-result pairings. Iterating at the correct item level, preserving joins and testing multi-item examples matter because a plausible graph can contain invented associations without a parsing error.

The ADR's later resource-coverage account also differs from its earlier fixture-leaf coverage. Paths, leaf occurrences, predicates and ontology resources have different denominators. A count of mapped resources does not prove every array shape, optional branch, consumer interpretation or reverse transformation. The final July 2026 amendment records a particular historical corpus; it is not coverage evidence for the separate Property Pack candidate or an approval of a future governed model.

## Exchange contracts need an explicit scope

An implementer should identify the source schema version, target corpus, mapping version, allowed values, transformation choices and unsupported cases. A conversion that truncates time precision or collapses two distinctions needs an explicit contract. Passing validation after conversion does not demonstrate that every source distinction was preserved.

Accepted ADR-0066 withdrew full-schema round-trip as the greenfield Property Pack acceptance condition. Proposed ADR-0091 describes future ontology-first schema change and migration, including a worked comparison and human decisions about compatibility. Existing mapping work can inform that process without becoming an automatic adapter to a new model.

The practical value of linked data is inspectability: a reviewer can follow a resource to its relationships, source and version, and an implementer can run a precise check over a precise graph. That value depends on preserving the boundary between what a resource means, what the tooling has exercised and what the responsible people have authorised for use.
